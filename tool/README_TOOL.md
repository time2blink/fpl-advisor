# FPL Advisor Tool

Локальный инструмент: качает данные из открытого API FPL, ведёт ежедневные снимки в SQLite, считает рейтинги и ожидаемые очки (xP) с учётом календаря, следит за составами тебя/Стаса/Ромы и топ-50 мира, подбирает трансферы по бюджету. Результат — красивый дашборд и файл-брифинг для Claude.

## Шансы по данным FPL (v1.19, Дизайн 2)
Вкладка **«Матчи»** (календарь команд: CS % / xG / xGA / сложность FPL на 5–10 туров; сухие матчи и голы тура; исполнители стандартов по клубам), в **«Игроках»** — вид «Шансы на тур» (CS %, DC %, гол, 2+, ассист, Г/А, стандарты), в карточке игрока — «Шансы по турам», в «Трансферах» — **пары для ротации**, в «Рынке» — **владение за 24 ч / 3 дня / 7 дней**, в «Соперниках» — **тур вживую** и **владение в нашей лиге**. Всё считается из данных FPL; это ориентир, как и xP.

## Точность прогноза и журнал событий (v1.20)
`backtest.py`: карточка «Точность прогноза очков» (Дизайн 2, «Соперники и лига») и блок в brief. «Ретро» — прогноз пересчитан по данным до каждого тура и сверен с фактом; «Журнал» — реальные прогнозы (xP1 и ep_next FPL), сохранённые до дедлайна, сверяются после тура (таблица `forecast`). `eventlog.py`: при каждом запуске пишет смены цены и статуса игроков с временем (`price_event`, `status_event`), в brief — «События за 48 ч».

## Прошлые сезоны (v1.21)
`seasons.py`: итоги прошлых сезонов из `history_past` (таблица `player_season`). В xP прошлый сезон входит якорем с весом K/(n+K), где n — выходов на поле в этом сезоне; `config.json → prior_k` (4 по умолчанию, 0 — выкл.). В карточке игрока — блок «Прошлые сезоны» и метка доли прошлого сезона у xP. Подобрано бэктестом.

## Два дизайна (v1.18)
По умолчанию — **Дизайн 2 (светлый)**, сделан по макетам `mockups/light-v3`. Прежний вид — **Дизайн 1 (классический)**. Переключение: ⚙ Настройки (рядом с названием команды) → «Дизайн дашборда»; через `run.bat` выбор сохраняется в `config.json → "design"` (1 или 2). Оба файла собираются при каждом запуске: `out/dashboard_v1.html`, `out/dashboard_v2.html`; `out/dashboard.html` — выбранный. Вкладки и функции в обоих одинаковые.

## Вкладки дашборда (v1.7)
1. **Обзор** — вердикт по трансферам, ключевые цифры, чипы, внимание, ближайший план, лучшие ходы, календарь команды.
2. **Состав** — рекомендация Claude (из `claude_picks.json`, учитывает новости) и расчёт программы по xP отдельной вкладкой.
3. **Трансферы и план** — слабые звенья с запасными вариантами → лучшие одиночные ходы (и топ-4 двойных) → план на 8 туров с альтернативами и чипами.
3a. **Скаут-лист** (v1.17, отдельная вкладка) — игроки под наблюдением по приоритетам P1–P3, фильтр «Все / Мои / От Claude», поле «добавить игрока».
4. **Игроки** — поиск и рейтинг. По умолчанию — топ-списки; переключатель **«Весь рынок»** добавляет всех, кто сыграл от `wide_min_minutes` минут (метка «вне списков»). Поиск всегда ищет по всем (v1.13).
5. **Соперники и лига** — угроза перехвата моих целей → мини-лига → что сделают друзья → гонка за лигу → актуальность данных → сворачиваемый «Чёрный список».
6. **Рынок** — давление на цены, удача/перегрев.
7. **Топ-50** — что покупают и держат лучшие менеджеры мира.
8. **Изменения** — что изменилось с прошлого снимка.
**Карточка игрока** (клик по аватару или имени любого игрока — открывается именно тот, на кого нажал, даже если в строке их двое, v1.14): цифры, **«Следующие матчи»** — тур, соперник, дома/в гостях, сложность 1–5 словами, xP на тур (пустые и двойные туры отмечены); **«Очки в прошлых турах»** — столбики с очками, под ними тур, соперник (цвет = сложность, «·» = в гостях) и минуты, сверху итог и среднее (v1.12).

Подсказки: наведи курсор на заголовок колонки (подчёркнут точками), значок «?» или цветную метку — появится пояснение. Старые ссылки (#plan, #bl, #league) ведут в новые вкладки.

`assets/` — иконка и логотип приложения; `assets/icons/` — иконки чипов (`chip_*`) и интерфейса (`ui_*`) в SVG, чипы также в PNG. Все иконки встроены в дашборд.

## Рекомендация Claude (`claude_picks.json`)
Файл ведёт Claude: старт (11), скамейка (4), капитан, вице, пояснения по игрокам. Дашборд показывает его на вкладке «Состав» и берёт из него капитана и вице в шапке. Если файл относится к другому туру или не совпадает с текущими 15 игроками, дашборд предупредит. Хочешь изменить состав — скажи Claude («поставь Foden в старт»), он внесёт правку.

## Ярлык на рабочий стол
Готовый ярлык `FPL Advisor.lnk` лежит в папке `tool`: скопируй его на рабочий стол (перетащи с зажатым Alt или правый клик → Копировать, затем на рабочем столе Вставить). Он указывает на `<папка-проекта>\tool\run.bat`; если папка проекта переедет, создай ярлык заново через `create_shortcut.bat`.

Один раз запусти `create_shortcut.bat` (двойной клик): на рабочем столе появится «FPL Advisor» с иконкой. Дальше достаточно открывать ярлык: данные обновятся, дашборд откроется в браузере. Если рабочий стол перенесён в OneDrive, скрипт сам найдёт правильную папку. Не получилось — правый клик по `run.bat` → Отправить → Рабочий стол (создать ярлык), иконку можно выбрать из `assets/fpl_advisor.ico` (Свойства → Сменить значок).

## Запуск (Windows)
1. Нужен Python 3.8+ (`python --version`). Ничего устанавливать через pip не нужно.
2. Двойной клик по `run.bat` (или ярлык). Через ~30 секунд дашборд откроется по адресу `http://127.0.0.1:8765/dashboard.html`. **Пока чёрное окно открыто**, работают ⚙ Настройки и пересчёт из браузера; закончил — закрой окно (в фоне ничего не остаётся). `python fpl_tool.py` без `--serve` просто считает и завершается (для планировщика).
3. Файл `out/claude_brief.md` отправь Claude (в чат или просто скажи «читай tool/out/claude_brief.md») — Claude проверит новости (травмы, пресс-конференции, составы) и примет финальное решение.

## ⚙ Настройки (v1.15)
Кнопка ⚙ справа от названия команды на «Обзоре». Там: **мой ID**, **соперники** (от 1 до 5; ID + имя, пустое имя подтянется из FPL), **ID мини-лиги** (необязательно). ID менеджера — число из адреса страницы «Очки»: `fantasy.premierleague.com/entry/1234567/event/8`. Каждый ID сразу проверяется в FPL. «Сохранить и пересчитать» пишет `config.json` (старая версия — в `data/config_history`, хранятся 5 последних) и обновляет данные. Сохранение работает только когда дашборд открыт через `run.bat` (адрес 127.0.0.1); открытый как файл — только просмотр. При смене менеджера его `pending` сбрасывается. Порт — `serve_port` в `config.json` (по умолчанию 8765). Так анализатор можно отдать Стасу/Роме: каждый ставит свой ID и ID соперников.

## Отдать другу (v1.16)
Двойной клик по `make_friend_pack.bat` → в папке проекта появится `dist/FPL_Advisor_for_friend.zip` (откроется в Проводнике). Внутри — папка `FPL_Advisor` (инструмент без `cache/`, `out/`, `data/`, `mock/`, `claude_picks.json` и ярлыка) и `ПРОЧТИ_МЕНЯ.txt` с шагами для друга. В копии `config.json` очищены `pending`, `blacklist`, `watchlist`; ID и имена остаются твои — друг поменяет их через ⚙. Твои файлы не меняются. Логика — `pack.py`.

Дашборд открывается в браузере автоматически после расчёта (отключить: `--no-open` или `"open_browser": false` в `config.json`).

Параметры: `--no-history` (быстрее, без истории игроков по турам), `--offline` (демо из `mock/`, без сети), `--serve` (после расчёта держать дашборд с настройками на 127.0.0.1, пока открыто окно; его включает `run.bat`).

- `serve.py` — локальный режим с настройками (только 127.0.0.1, только пока открыто окно `run.bat`).

- `data/fpl.db` — база снимков (копится со временем: тренды, новые/вылетевшие игроки, динамика цен и владения). Бэкап = просто копия этого файла.

## Как считается
**xP = expected points, ожидаемые очки** — прогноз среднего числа очков FPL за матч/тур (xP1 — на ближайший тур, xP5 — за 5 туров). Объяснение есть и на вкладке «Обзор» дашборда.
- **xP (ожидаемые очки)** = (0.7·(0.5·очки/игру + 0.5·форма) + 0.3·среднее по позиции — защита от перегрева формы) × поправка на сложность матча (+10% за каждый уровень ниже 3) × вероятность выйти на поле (по минутам) × доступность (травмы/шанс) — по матчам ближайших 5 туров. Двойные туры учитываются, отсутствие матча = 0.
- **Рейтинг (0–100)** внутри позиции: очки/игру, форма, xGI/90 (защитники — защитные действия и xGC, вратари — xGC), календарь, минуты, очки за £; домножается на доступность.
- **Цена продажи**: покупка + половина прибыли (округление вниз) — как в FPL. Цена покупки берётся из истории трансферов; для стартового состава — стартовая цена.
- **Банк и FT** — из API (банк на дедлайн + ходы на ближайший тур) и оценка свободных трансферов по истории. Если FT не сходится, поставь `free_transfers_override`.
- **Доступность игроков** — по актуальным составам Стаса и Ромы (правило «без повторов»).
- **Предложения**: одиночные и двойные ходы в пределах банка, лимит 3 игрока из клуба, хит учитывается; список «слабых звеньев» и страховка (3 запасных варианта по каждому игроку).
- **Тренды** (цена/владение/форма за неделю, новые и вылетевшие игроки) появятся со второго снимка.

## Важно: ходы на ближайший тур до дедлайна API не показывает
Публичный API отдаёт трансферы только до последнего дедлайна. Поэтому если ты (или друзья) уже сделали ходы на GW8, а дедлайн ещё не прошёл, инструмент видит состав **на дедлайн GW7**. Решение — блок `pending` в `config.json`: впиши свой текущий состав (имена как в FPL, при неоднозначности `Имя:КЛУБ`), `bank` в десятых (3 = £0.3m) и `ft` (свободные трансферы). Для Стаса/Ромы добавь `pending.stas` / `pending.roma`, если они уже сделали ходы. После дедлайна API всё покажет сам, `pending` можно очистить. Цена продажи для только что купленных игроков считается как текущая цена (приближение).

## Чёрный список и слежение за друзьями
Игроки из составов Стаса и Ромы исключаются из рекомендаций автоматически. Свой чёрный список ведётся двумя способами: раздел «Чёрный список» на вкладке «Соперники и лига» (хранится в браузере) или `config.json → "blacklist"` (тогда его учитывают и расчёты, и brief для Claude). Исключённые не попадают в трансферы, замены при травме и топ-списки для покупки, но их статистика продолжает собираться.

**Слежение.** Укажи, чей игрок: в дашборде выбери «Стас/Рома» рядом с игроком, а в конфиге пиши `"Cherki:MCI@stas"` (или `{"player": "Cherki:MCI", "owner": "stas", "pin": false}`). На каждом запуске инструмент сверяет составы друзей:
- **у друга** — игрок остаётся в чёрном списке;
- **ждём дедлайн** — API не показывает ходы на ближайший тур до дедлайна, поэтому статус не подтверждён и игрок остаётся заблокирован;
- **освободился** — после дедлайна (или если состав друга внесён в `pending`) игрока в составе уже нет. Он автоматически снова доступен для рекомендаций, появляется уведомление на обзоре, во разделе «Чёрный список» (вкладка «Соперники и лига») и в `claude_brief.md`; там кнопки «Оставить в ЧС» и «Убрать».
Также показывается блок «Ходы друзей с прошлого снимка»: кто что продал и купил.

## Аналитические блоки (v1.0)
- **План** — ходы на 8 туров вперёд с учётом FT, банка и хитов + лучшие туры для чипов. Расчёт по xP, не знает про травмы будущего: после изменения новостей запускай заново.
- **Соперники** — вероятные продажи и покупки Стаса/Ромы и угроза перехвата твоих целей. До дедлайна API не показывает их новые ходы, поэтому это вероятностная модель; внеси их реальные составы в `pending.stas` / `pending.roma`, и оценка станет точнее.
- **Рынок** — давление на цену (по чистым трансферам; калибруется историей) и список недоудачливых/перегретых игроков.
- **Гонка** — симуляция сезона для тебя и соперников, режим игры по ситуации.
- **Экспорт** — `out/export/players.csv`, `my_squad.csv`, `plan.csv`, `threats.csv` (Excel). `out/run.log` — история запусков.
- Новые параметры (v1.10): `max_hits_per_gw` (лимит платных трансферов за тур в плане), `deny_weight` (вес эффекта блокировки друзей, 0 — выключить), `chip_expiry_gw` и `chip_expiry_deadline` (срок сгорания первого набора чипов), `weak_include_bench` (учитывать скамейку в слабых звеньях).
- Параметры в `config.json`: `planner_horizon` (по умолчанию 8), `chip_halves` и `chip_reset_gw` (чипы: два набора; первый сгорает после дедлайна GW19, второй с GW20 — проверено).

## Скаут-лист (watchlist)
В `tool/config.json → "watchlist"` ведётся список игроков под наблюдением: `{"player":"Имя:КЛУБ","prio":1..3,"note":"...","trigger":"..."}`. Дашборд показывает его на отдельной вкладке «Скаут-лист» (цена, форма, xP5, календарь, свободен/занят, травма, сигнал «лучше слабого звена»), а также `claude_brief.md`. Список обновляет Claude после каждой сессии и новостей (возвраты из травм, новые гемы, перехваты у друзей); не затирай решения пользователя. Скаут-лист — это наблюдение и триггеры, а расчётные «Лучшие ходы» строятся отдельно по xP.

**Свои игроки (v1.17).** Добавить можно кнопкой «В скаут-лист» в карточке любого игрока (там же приоритет P1–P3 и заметка) или полем на вкладке «Скаут-лист»; убрать — ✕ на карточке или «Убрать» в карточке игрока. Такие записи получают `"source":"user"`, `"fpl_id"` и `"added"` (дата), на дашборде выделены оранжевой рамкой и меткой «добавил Женя», а в `claude_brief.md` — пометкой `[ДОБАВИЛ ЖЕНЯ дата]`, чтобы Claude их оценил. Запись Claude при изменении приоритета остаётся записью Claude.
- Дашборд открыт через `run.bat` (адрес `http://127.0.0.1:…`, окно не закрыто) — изменения сразу пишутся в `config.json` (старая версия — в `data/config_history`). Пересчёт не нужен: Claude читает `config.json`, brief обновится при следующем запуске.
- Дашборд открыт как файл — изменения хранятся только в этом браузере (localStorage); на вкладке появится JSON для ручной вставки, а при следующем открытии через `run.bat` — кнопка «Сохранить в config.json».

## Откуда данные и когда пересчитывать
**Роли.** Мозг — Claude: принимает решения, ищет новости (травмы, пресс-конференции, вероятные составы). Интерфейс и БД — только помощники: показывают пользователю картину и помогают Claude держать данные свежими (особенно историю снимков в SQLite).

**Откуда данные.**
- *API FPL (авто):* цены, форма, очки, владение, травмы-флаги, календарь, составы/банк/трансферы всех трёх менеджеров **до последнего дедлайна**, ходы топ-50.
- *Вручную в `config.json → pending`:* составы/банк/FT на ближайший тур, пока дедлайн не прошёл (API их скрывает). Для Стаса и Ромы заполнено на 20.10.2026 и подтверждено пользователем. После дедлайна API показывает реальные составы, `pending` игнорируется с предупреждением.
- *Новости (Claude, поиск):* пресс-конференции, вероятные составы, сроки травм — в API нет.
- *Оценки модели (не факты):* xP, план, вероятные ходы друзей, давление на цену, гонка.

**Динамика, которую надо учитывать.**
1. План на 8 туров и все xP считаются по xP-модели и **не знают о новостях**. После любой важной новости (травма, ротация, смена роли, ходы друзей) пересчитывай: перезапусти инструмент (`run.bat`/`fpl_tool.py`) и перечитай brief.
2. «Угрозы от друзей» работают точно только если Claude знает реальные изменения составов Стаса/Ромы перед стартом тура или в его начале. Проси у пользователя скрин/список (или вноси сам в `pending.stas`/`pending.roma`).
3. Чипы: два набора; первый нужно сыграть до дедлайна GW19 (2 января 2027, 13:30 GMT), иначе он сгорает; второй с GW20 (проверено по статье Premier League от 20.07.2026).
4. Если пользователь просит «глобально поменять/пересчитать» (новая стратегия, чип, массовые трансферы) — сначала убедись, что данные свежие: дата последнего снимка, `pending` актуален, банк/FT совпадают с приложением, новости проверены. Чего не хватает — запроси у пользователя или обнови сам (запуск инструмента, правка `config.json`, поиск новостей), и только потом считай.

## Нагрузка на API и размер базы
- **Кэш ответов** (`cache/`, файлы старше 3 суток удаляются сами): каждый запрос запоминается на время, зависящее от того, как часто данные реально меняются: составы тебя/Стаса/Ромы — 5 минут, общие данные (цены, новости) — 10 минут, топ-50 — 1 час, календарь — 6 часов, история игроков — 12 часов, составы топ-менеджеров за сыгранный тур — 24 часа. Запускай `run.bat` хоть 30 раз в день: повторные запуски идут из кэша и в сеть почти не ходят. Принудительно перекачать всё: `python fpl_tool.py --refresh`.
- **Объём истории по турам** (v1.13): `element-summary` качается для пула + всех, кто сыграл от `wide_min_minutes` минут, + свои/друзей/скаут-лист/чёрный список — на 21.10.2026 это ~350 игроков (~26 с полный запуск, дашборд ~0.8 МБ). Брать всех ~670 смысла нет: +500 запросов на запуск ради игроков без минут. Меньше нагрузки — подними порог (например 270) или запускай с `--no-history`.
- **Вежливость к API:** не больше ~8 запросов в секунду суммарно, 4 потока, при ответе 429 («притормози») программа ждёт и повторяет; если сеть или API недоступны, она берёт устаревший кэш и предупреждает об этом в итоговой строке.
- **База (`data/fpl.db`): один снимок в сутки.** Повторный запуск в тот же день обновляет сегодняшний снимок, а не добавляет новый. Старше 90 дней (`retention_days` в конфиге) остаётся по одному снимку в неделю. Ориентир: сезон — десятки мегабайт, не гигабайты.
- **Защита базы:** перед любой записью делается копия `data/backup/fpl_ГГГГММДД.db` (раз в день, хранится только 3 последние — лишнее удаляется само, чистить вручную ничего не нужно), при запуске проверяется целостность — если база повреждена, она откладывается в сторону (`.corrupt-…`) и восстанавливается из последней копии. Двойной запуск блокируется (`data/.lock`).
- Старую базу с несколькими снимками за день программа при первом запуске сама сводит к одному снимку на день.

## Ограничения
- Работает локально у каждого. Рядом работает облачный конвейер сбора данных для мобильного приложения (`github-check/`, GitHub Actions раз в 3 часа → публичный репо `fpl-advisor-data`, включая `state/fpl.db.gz`). Идея облачной версии с общей базой и Telegram Mini App отложена — описание: [../references/idea-cloud-telegram.md](../references/idea-cloud-telegram.md).
- В API нет вероятных составов и пресс-конференций — это ищет Claude по новостям.
- Прогноз изменения цены — по чистому потоку трансферов (ориентир, не точный расчёт).
- Расчёт xP — эвристика; финальное решение всегда принимает Claude/ты.
